Справочник Виды событий

Назначение

Справочник "Виды событий"﻿ предназначен для хранения информации о видах событий для рассылки оповещений.

Для корректной работы системы оповещений необходимо:

  • Включить опцию "Использовать оповещения" в Параметрах подсистемы PM в группе "Оповещения";
  • Включить события, оповещения о которых будет приходить пользователю, в справочнике "Виды событий";
  • Настроить системную учетную запись, от имени которой будут рассылаться письма, в справочнике Учетные записи электронной почты;
  • Указать e-mail для отправки писем в справочнике Пользователи;
  • Выбрать виды событий в форме Персональные настройки в группе "Оповещения" (либо в регистре сведений Подписки на оповещения, либо в справочнике Пользователи на вкладке "Подписки на оповещения");
  • Настроить время выполнения регламентных заданий "Обработка произошедших событий" и "Обработка очереди оповещений".

    • Справочник содержит предопределенные элементы, а также позволяет создавать новые виды событий.

    Для предопределенных видов событий допустимы только следующие действия с помощью кнопок на командной панели формы:

  • включение/выключение использования вида события; 
  • редактирование состава транспорта оповещений.

    • При необходимости, предопределенные виды событий можно скопировать, отключить и настроить новые пользовательские виды событий под конкретные нужды пользователей.

    Предопределенные виды событий: 

  • Группа "Задания": 
  • Назначение на проектную задачу – при назначении исполнителя (трудового ресурса) на проектную задачу направляется оповещение диспетчеру этого трудового ресурса;
  • Новое задание – при выдаче нового задания направляется оповещение диспетчеру трудового ресурса, указанного в качестве исполнителя задания.
  • Группа "События проекта":
  • Возобновление проекта – при создании (проведении) документа Возобновление проекта направляется оповещение диспетчеру руководителя / куратора проекта;
  • Завершение проекта – при создании (проведении) документа Завершение проекта направляется оповещение диспетчеру руководителя / куратора проекта;
  • Остановка проекта – при создании (проведении) документа Остановка проектных работ направляется оповещение диспетчеру руководителя / куратора проекта;
  • Регистрация проекта – при создании (проведении) документа Регистрация проекта направляется оповещение диспетчеру руководителя / куратора проекта;
  • Старт проекта – при создании (проведении) документа Старт проектных работ направляется оповещение диспетчеру руководителя / куратора проекта;
  • Утверждение плана проекта – при создании (проведении) документа Утверждение плана проекта направляется оповещение диспетчеру руководителя / куратора проекта.

    • Форма списка объектов справочника

    На форме списка объектов справочника расположены следующие кнопки:

  • Включить/выключить – включает / выключает регистрацию выделенного события и обработку его в очереди произошедших событий (регламентное задание "Обработка произошедших событий") и очереди оповещений (регламентное задание "Обработка очереди оповещения");
  • Включить/выключить транспорт – включает / выключает виды транспорта, в том числе у предопределенных видов событий;
  • Запустить детектор – запускает регламентное задание "Обработка детекторов событий" у видов событий со способом отслеживания "По расписанию". Приведена в форме для тестирования детектора, написанного на закладке "Детектор события";
  • Тест отправки сообщений – позволяет протестировать отправку сообщения по заданным условиям.

    • Форма объекта

    Форма элемента справочника состоит из общей части и закладок.

    Общая часть

    Общая часть содержит следующие реквизиты:

  • Наименование – наименование события;
  • Способ отслеживания события:
  • По расписанию – система отправляет оповещения по заданному расписанию по объекту системы, для которого настроен механизм оповещений с учетом заданных условий. Данный вид событий появляется в обработке Регламентные и фоновые задания. По кнопке Запустить детектор можно запустить выполнение задания принудительно, игнорируя расписание.
  • При записи объекта – система отправляет оповещение в момент действия над объектом системы, для которого настроен механизм оповещений с учетом заданных условий.
  • Источник – вид объекта системы (документ, справочник, регистр, бизнес-процесс), для которого настраивается данный вид события;
  • Вариант изменения объекта – выбор варианта действия над объектом, при выполнении которого будет регистрироваться новое событие для оповещения. Список вариантов (запись, проведение, перепроведение, отмена проведения, пометка на удаление и др.) зависит от вида объекта. Реквизит доступен при способе отслеживания события "При записи объекта";
  • Расписание – ссылка на расписание регламентного задания "Обработка произошедших событий". Настройка расписания доступна при способе отслеживания события "По расписанию".

    • Закладка "Сообщение"

    На закладке "Сообщение" в левой части по кнопке Добавить формируется перечень тэгов для шаблона сообщения, в правой части – добавляется шаблон сообщения для данного вида события.

    В шаблоне сообщения могут использоваться следующие типы тэгов:

  • Реквизит объекта - стандартные реквизиты выбранного объекта;
  • Дополнительный реквизит объекта - реквизиты и сведения, добавленные к объекту пользователем;
  • Вычисляемый реквизит - реквизит, который не хранится в базе, а вычисляется при обращении к реквизиту (например, есть предопределенные вычисляемые реквизиты для Проектов, Проектной задачи и Заданий);
  • Константа - любая константа в базе данных;
  • Выполняемый код - код, написанный на встроенном языке 1С;
  • Навигационная ссылка - ссылка на объект текущей базы, состоит из адреса базы и адреса самого объекта (адрес базы задается в Параметрах подсистемы PM в группе "Оповещения").

    • Например, у тэга "Вычисляемый реквизит" у документа "Проектная задача" доступны следующие значения:

  • Статус задачи;
  • Руководитель задачи;
  • Дата начала;
  • Наименование задачи;
  • Дата завершения;
  • Процент готовности.

    • Шаблон темы будет доступен, если в качестве транспорта оповещений выбран тип "Электронная почта".

    Рекомендуется задавать обычный текст сообщения(нужен для SMS оповещения, оповещения по Электронной почте и оповещения с помощью заданий) и HTML (используется при оповещении по Электронной почте).

    Закладка "Детектор событий"

    На закладке "Детектор событий" можно задать произвольные условия на встроенном языке системы. Например, можно настроить оповещение пользователя при достижении показателями на проектах определенных значений. Данная закладка появляется при способе отслеживания события "По расписанию".

    Закладка "Условия регистрации события"

    На закладке "Условия регистрации события" указываются отборы, при выполнении которых необходимо формировать оповещения по конкретному виду события. Реквизиты закладки:

  • Если опция "Не регистрировать повторно" включена, то, в случае наличия успешно отправленного сообщения для определенного объекта, повторное выполнение условий для него не приведет к регистрации события. Успешно отправленные сообщения хранятся в регистре сведений Отправленные сообщения.
  • Если опция "Использовать для анализа предыдущие значения" включена, то, при вводе условий в табличной части выполняемым кодом, будет доступна переменная "ДанныеДоИзменения"
  • Код определения доп.параметра позволяет прописать на встроенном языке дополнительное измерение источника события. Т.е. по одному объекту можно зарегистрировать несколько событий в зависимости от значений этого параметра. Например, документ Назначение трудовых ресурсов на проектную задачу и значения параметра "Овечкин А.И." и "Петров З.К".

    • Закладка "Транспорт оповещений"

    На закладке "Транспорт оповещений" необходимо выбрать способ доставки оповещений из справочника Транспорт оповещений – по электронной почте, SMS или с помощью заданий.

    Закладка "Получатели"

    На закладке "Получатели" можно указать конкретных получателей по данному виду события и задать, при необходимости, ограничения и дополнительные условия.

    Например, можно в колонке "Получатели" для вида получателей из справочника Пользователи указать конкретных пользователей, тогда подписаться на этот вид событий смогут только пользователи, указанные в колонке "Получатели". Если в табличной части несколько строк с различными отборами, то каждая строка будет исполняться отдельно.

    Закладка "Дополнительно"

    На закладке "Дополнительно" можно указать сервисные настройки отправки оповещений и дополнительные параметры.

    Реквизиты закладки:

  • Количество попыток отправки – количество попыток отправки сообщения;
  • Срок хранения оповещений – количество дней хранения оповещений в регистре сведений Очередь событий для оповещений;
  • Принудительно – опция включает запрет на отмену рассылки оповещений для получателей.

    • В табличной части "Дополнительные параметры выполняемого кода" указываются дополнительный параметры, которые используются в коде условий, коде для определения дополнительных параметров источника на закладке "Условия регистрации событий", на закладке "Получатели", на странице детектора событий, в тэгах с исполняемым кодом на закладке "Сообщение".
