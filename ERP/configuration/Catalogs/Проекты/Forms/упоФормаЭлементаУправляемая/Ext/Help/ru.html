Справочник Проекты



Если в справке напротив поля или элемента интерфейса есть иконка, то элемент доступен только в приложении "1С:PM Управление проектами КОРП" (1С:PM КОРП).

Назначение

Основным структурным объектом учета и управления в системе является проект.

Проект – ограниченный во времени комплекс взаимосвязанных мероприятий, проводимых предприятием с целью получения уникальных продуктов и/или результатов.

Справочник "Проекты" позволяет фиксировать и хранить в системе информацию о проектах.

Форма объекта

На командной панели элемента справочника "Проекты" расположены следующие кнопки:

  • Кнопка Записать и закрыть – сохраняет измененные данные, введенные в элемент справочника "Проекты" и закрывает форму элемента. 
  • Кнопка Записать – сохраняет измененные данные, введенные в элемент справочника "Проекты". 
  • Кнопка Создать на основании – позволяет создать на основании выбранного проекта некоторые виды документов, связанные с регистрацией фактических данных по проекту, актуализацией данных проекта и т.п. В созданных таким образом документах реквизит "Проект" будет заполняться автоматически текущим значением проекта. 
  • Кнопка Зарегистрировать проект – позволяет создать документ Регистрация проекта на основании текущего проекта (кнопка отображается только для проектов, которые не были зарегистрированы); 
  • Кнопка Структура проекта – открывает обработку Структура проекта для ввода плана работ по проекту. 
  • Кнопка Открыть монитор проекта – открывает обработку Монитор проекта. 
  • Кнопка Схема показателей проекта – открывает обработку Дерево ключевых показателей проекта в соответствии с указанной в реквизите "Настройка дерева ключевых показателей" (закладка "Опции проектной модели") настройкой. Если реквизит не заполнен, будет предложено выбрать настройку при открытии обработки. 
  • Кнопка Сетевой график – открывает отчет Сетевой график, который показывает структуру проекта в виде сетевого графика. 
  • Кнопка Статусы проекта – открывает журнал документов Статусы проекта с отобранными по данному проекту документами. 
  • Кнопка Риски – открывает справочник Риски проектов с установленным отбором по текущему проекту. 
  • Кнопка Управление версиями проекта – открывает обработку Управление версиями проекта, которая позволяет просматривать/добавлять/редактировать/помечать на удаление версии выбранного проекта. 
  • Кнопка Статус-отчеты → Открыть сводные статус-отчеты по проекту – открывает реестр документов Сводный статус-отчет по проектам, содержащих текущий проект;
  • Кнопка Статус-отчеты → Открыть статус-отчеты по проекту – открывает реестр документов Статус-отчет по проекту с отбором по текущему проекту;

    • Важно! Кнопка Статус-отчеты доступна при включенной опции "Использовать статус-отчеты по проектам" в Параметрах подсистемы PM в группе "Статус-отчеты по проектам".

  • Кнопка Задания → Открыть задания – открывает перечень заданий по текущему проекту. 
  • Кнопка Задания → Открыть проектные решения – открывает перечень проектных решений по текущему проекту. 
  • Кнопка Задания → Открыть задания на планирование – открывает перечень заданий на планирование этапа проекта (с признаком "Задание подразделению" и видом задания "Задание на планирование") по текущему проекту;
  • Кнопка Задания → Открыть задания на прогноз – открывает перечень заданий на прогноз (с признаком "Задание подразделению" и видом задания "Задание на прогноз") по текущему проекту;
  • Кнопка Хозяйственные операции проекта – открывает обработку Хозяйственные операции проекта, в которой отображаются все заведенные в системе документы, относящиеся к текущему проекту (в том числе непроведенные, если установлен соответствующий отбор). 
  • Кнопка Открыть панель руководителя по программе – открывает обработку Панель руководителя с отбором по программе проектов, в которую включен данный проект.
  • Кнопка Отчеты – открывает перечень отчетов, которые можно сформировать по текущему проекту. 
  • Кнопка Импорт и экспорт → Сохранение проекта в шаблон – открывает обработку Сохранение проекта в шаблон, которая позволяет перенести данные из календарно-ресурсного плана проекта в шаблон проекта. 
  • Кнопка Импорт и экспорт → Создание проекта из шаблона – открывает обработку Создание проекта из шаблона, которая позволяет перенести данные из шаблона в календарно-ресурсный план проекта. 
  • Кнопка Импорт и экспорт → Экспорт в MS Project – открывает обработку Выгрузка данных в MS Project, которая позволяет выгрузить структуру проекта в Microsoft Project. 
  • Кнопка Импорт и экспорт → Импорт из MS Project – открывает обработку Импорт из MSP, которая позволяет загрузить график из Microsoft Project в качестве структуры выбранного проекта. 
  • Кнопка Импорт и экспорт → Загрузка из сметы – открывает обработку Загрузка из сметы, которая позволяет загрузить данные из локального файла в формате *arp в качестве структуры выбранного проекта.

    • Важно! Кнопка Импорт и экспорт → Загрузка из сметы доступна при включенной опции "Использовать загрузку из сметы" в Параметрах подсистемы PM в группе "Основные параметры".

  • Кнопка БДДС проекта – открывает обработку БДДС проекта для ввода данных по статьям бюджета движения денежных средств. 
  • Кнопка БДР проекта – открывает обработку БДР проекта для ввода данных по статьям бюджета доходов и расходов.
  • Кнопка Еще → Распределение БДР → Распределить БДР: Проект – запускает обработку Распределение БДР, которая позволяет выполнить распределение доходов и расходов во всех проектных задачах проекта по подразделениям с учетом трудозатрат. Распределение производится в соответствии с настройками, указанными в карточке проекта (реквизит "Настройка распределения БДР" на закладке "Опции проектной модели").
  • Кнопка Еще → Распределение БДР → Мастер распределения БДР: Проект – открывает обработку Распределение БДР, которая позволяет произвести распределение доходов и расходов во всех проектных задачах проекта по подразделениям с учетом трудозатрат. Распределение производится в соответствии с настройками, указанными непосредственно в обработке.

    • Форма элемента справочника "Проекты" состоит из общей части и закладок.

    При заполнении общей части справочника "Проекты" необходимо заполнить следующие обязательные реквизиты:

  • Наименование – наименование проекта; 
  • Код – формируется автоматически.

    • Закладка "Параметры"

    На данной закладке отображаются реквизиты, описывающие основные параметры проекта:

  • Полное наименование – полное наименование проекта;
  • Шифр – шифр проекта. При записи нового проекта реквизит автоматически заполняется значением кода проекта, если не был до этого заполнен вручную;
  • Краткое описание – краткая информация о проекте, не относящаяся к описанию целей, обоснований, ожидаемых результатов и выгод проекта, которые описываются на закладке "Цели".

    • Состояние проекта

  • Дата старта – информация о дате начала проекта, которая указывается в обработке Структура проекта;
  • Руководитель – информация о руководителе проекта, назначенном в документе Регистрация проекта;
  • Фаза – информация о текущей фазе проекта с закладки "Фазы";
  • Статус – информация о текущем статусе проекта с закладки "Статусы";
  • Куратор – информация о кураторе проекта, назначенном в документе Регистрация проекта.

    • Положение проекта в организационной и юридической структурах

  • Организация — элемент справочника Организации. Этот реквизит показывает, какой организацией выполняется проект. Реквизит не является обязательным для заполнения;
  • Бизнес-единица – элемент справочника Подразделения. Этот реквизит показывает, каким из подразделений предприятия выполняется проект. Реквизит не является обязательным для заполнения;
  • Программа проектов – элемент справочника Программы проектов. Этот реквизит показывает, какой программе проектов принадлежит данный проект. Реквизит не является обязательным для заполнения;
  • Кнопка Открыть структуру программы – открывает структуру основного проекта программы, указанной в реквизите "Программа проектов";
  • Портфель проектов – элемент справочника Портфели проектов. Этот реквизит показывает, какому портфелю проектов принадлежит данный проект. При заполнении реквизита, при условии что проект уже записан в системе, производится запрос на использование функциональных опций из указанного портфеля (установить опции и реквизиты на закладке "Опции проектной модели" в соответствие со значениями, указанными в портфеле, а также заменить настройку показателей на закладке "Показатели" на указанную в портфеле). Реквизит не является обязательным для заполнения;
  • Кнопка Открыть структуру портфеля – открывает структуру основного проекта портфеля, указанного в реквизите "Портфель проектов".

    • Характеристики

  • Компонент – по умолчанию для проектов выбирается значение "Проект", также возможны варианты "Программа проектов" и "Портфель проектов";
  • Тип проекта – элемент справочника Типы проектов. Этот реквизит показывает, к какому типу проекта принадлежит данный проект. Реквизит не является обязательным для заполнения. В зависимости от выбранного типа проектов, к проекту может быть привязан набор регистрируемых вручную показателей проектов. Показатели выводятся на закладку "Показатели" в табличную часть "Показатели со значениями, регистрируемыми вручную". Набор показателей настраивается непосредственно в элементе справочника Типы проектов;
  • Объект – элемент справочника Объекты. Этот реквизит показывает, к какому объекту относится данный проект. Реквизит не является обязательным для заполнения;
  • Сложность проекта – элемент справочника Сложность проектов. Этот реквизит показывает, к какой сложности относится данный проект. Реквизит не является обязательным для заполнения;
  • Направление инвестиций – элемент справочника Направления инвестиций. Этот реквизит показывает, к какому направлению инвестиций относится данный проект. Реквизит не является обязательным для заполнения;
  • Источник финансирования – элемент справочника Источники финансирования. Этот реквизит показывает, к какому источнику финансирования относится данный проект. Реквизит не является обязательным для заполнения;
  • Приоритет - дополнительная оценочная аналитика проекта. Заполняется вручную или по кнопке Заполнить приоритет расчетными данными, также заполняется из связанного с проектом документа Соответствие стратегическим целям по кнопке "Записать баллы в приоритеты проектов". Реквизит не является обязательным для заполнения;
  • Кнопка Заполнить приоритет расчетными данными – автоматически заполняет реквизит "Приоритет" баллами по проекту из последнего введенного документа Соответствие стратегическим целям;
  • Кнопка Открыть документы приоритета – открывает список введенных по проекту документов Соответствие стратегическим целям.

    • Прогнозные сроки

  • Дата начала – прогнозируемая дата старта проекта. Данный реквизит является информационным и не используется для расчета сроков проекта. Реквизит не является обязательным для заполнения;
  • Дата завершения – прогнозируемая дата завершения проекта. Данный реквизит является информационным и не используется для расчета сроков проекта. Реквизит не является обязательным для заполнения;
  • Статус сроков – экспертная оценка соблюдения прогнозируемых сроков.

    • Важно! Реквизиты "Дата начала", "Дата завершения", "Статус сроков" недоступны для редактирования до момента регистрации проекта в системе.

    Характеристики

    Раздел содержит текстовое поле для дополнительной информации о проекте.

    Закладка "Цели"

    На закладке "Цели" можно указать цель, ожидаемые результаты, выгоды и обоснования проекта.

    Закладка "Фазы"

    Фаза проекта представляет собой набор действий и условий, которые необходимо выполнить для достижения следующей контрольной точки проекта. Фазы проекта позволяют отслеживать прохождение ключевых точек (вех) проекта, которые являются воротами качества проекта.

    Количество вех в проекте может быть достаточно большим, тогда как количество ключевых точек обычно невелико и именно по прохождению ключевых вех проекта система позволяет отслеживать, на какой стадии находится выполнение проекта.

    Закладка "Фазы" состоит из схемы фаз и таблицы фаз. Схема фаз отображается в случае, если заполнена таблица фаз.

    Для управления отображаемыми на схеме фаз данными служат кнопки:

  • Кнопка Обновить схему – предназначена для обновления схемы фаз проекта;
  • Кнопка Таблица фаз – включает/отключает отображение под схемой фаз таблицы настройки фаз, в которой сопоставляются фазы и ключевые вехи проекта;
  • Кнопка Учитывать сроки – при нажатой кнопке, схема фаз масштабируется и выводится на временной шкале с учетом сроков вех. Текущая дата на схеме отображается вертикальной красной пунктирной линией. Если кнопка не нажата, сроки вех не учитываются;
  • Кнопки Год, Квартал, Месяц – позволяют задавать масштаб схемы фаз. Кнопки доступны только если нажата кнопка Учитывать сроки;
  • Кнопка ВК/Вид операции – включает / отключает вывод на схему фаз наименования ворот качества (видов операций) в блоках вех.

    • На схеме фаз:

  • над блоками вех выводятся порядковые номера вех из таблицы фаз и наименования проектных вех;
  • в блоках фаз выводятся порядковые номера фаз из таблицы фаз и их наименования;
  • под блоками фаз выводятся их полные наименования.

    • Для управления таблицей фаз служат кнопки:

  • Кнопка Добавить – добавляет новую строку в таблицу фаз;
  • Кнопка Текущая – позволяет отметить текущую фазу, на которой сейчас находится определенный проект. На схеме фаз будет обновлено изображение фаз, текущая фаза будет выделена цветом и указывающей на нее стрелкой;
  • Кнопка Проектные решения вехи – позволяет создать и просмотреть проектные решения, относящиеся к конкретной вехе. Проектные решения позволяют контролировать выполнение задач по конкретной фазе проекта. Созданные проектные решения для вехи будут отображены (с указанием исполнителя) на схеме фаз под соответствующей фазой.

    • Примечание. Когда статус проектного решения изменяется на "Завершено", на схеме фаз данное задание выделяется зеленым цветом и ставится пометка о его выполнении. Если проектное решение было установлено как основное, в схеме фаз оно будет выделено полужирным начертанием.

  • Кнопка Индикатор по фазе – на закладке "Дополнительно" возможно указать "Основной индикатор по фазе", выбрав показатель из справочника Показатели проектов. Индикатор по фазе используется для отображения прогресса фазы на схеме фаз. Показатель рассчитывается для каждой вехи отдельно и должен удовлетворять следующим условиям: 

  • индикатор рассчитывается для проектных задач; 
  • значение показателя попадает в диапазон от 0 до 100.
  • Кнопка Заполнить по структуре – предназначена для автоматического заполнения таблицы фаз на основании графика проекта.

    • Таблицу фаз возможно заполнить вручную или автоматически.

    Ручное заполнение таблицы фаз

    Ручное заполнение таблицы фаз производится по кнопке Добавить. Табличная часть состоит из следующих колонок:

  • Текущая фаза – символ "→" указывает, какая фаза на данный момент является текущей (устанавливается при выделении в таблице конкретной фазы и нажатии кнопки Текущая);
  • N – номер фазы, заполняется автоматически по порядку;
  • Фаза – наименование фазы, при этом первая фаза по умолчанию называется "Стартовая". Значение выбирается из справочника Фазы проектов;
  • Веха – указывается конкретная ключевая веха данного проекта, соответствующая выбранной фазе.

    • В качестве вехи может быть выбрана проектная задача типа "Веха", заданная в структуре данного проекта.

    Автоматическое заполнение таблицы фаз

    Для возможности автоматического заполнения таблицы фаз необходимо произвести следующие настройки в структуре проекта:

  • Для ключевых точек (вех) проекта, которые являются воротами качества и должны быть сопоставлены с конкретной фазой в таблице фаз необходимо указать в проектной задаче: 
  • тип проектной задачи – "Проектная задача является вехой"; 
  • выбрать вид операции для данной проектной задачи и при этом в выбранном из справочника Виды операций элементе должен стоять флаг "Ворота качества".
  • Структура проекта должна быть выстроена в следующей иерархии: 
  • верхний уровень – проектная задача типа "Этап"; 
  • на вложенном уровне – проектная задача типа "Веха" (этап является родителем для вехи).

    • При данной настройке по кнопке Заполнить по структуре будет автоматически заполнена табличная часть "Таблица фаз" следующим образом:

  • Фаза – будут созданы элементы справочника Фазы проектов, названия будут соответствовать этапам графика проекта. При этом первая фаза по умолчанию будет "Стартовая";
  • Веха – ключевые точки проекта будут сопоставлены с фазами на основании иерархии в графике работ по проекту (фаза, созданная в соответствии с этапом проекта, будет сопоставлена с относящейся к этому этапу вехой).

    • Закладка "Статусы"

    Данная закладка служит для управления статусами проекта.

    На закладке доступны следующие кнопки, соответствующие возможным статусам проекта:

  • Без статуса – проект еще не прошел стадию инициации;
  • Запланирован – проект прошел стадию инициации и находится в стадии планирования. При назначении данного статуса создается документ Регистрация проекта;
  • Утвержден – проект прошел стадии планирования и утверждения, но еще не прошел стадию запуска. При назначении данного статуса создается документ Утверждение плана проекта;
  • Выполняется – проект прошел стадию запуска и находится в стадии выполнения. При назначении данного статуса создается документ Старт проектных работ. Если проект был остановлен или завершен, а позднее возобновлен, то создается документ Возобновление проекта;
  • Остановлен – проект по каким-либо причинам временно или окончательно остановлен на этапе выполнения. При назначении данного статуса создается документ Остановка проектных работ;
  • Завершен – проект прошел стадии выполнения и завершения. При назначении данного статуса создается документ Завершение проекта.

    • Кнопка, соответствующая текущему статусу проекта, подсвечена голубым цветом. Также текущий статус проекта отображается на закладке "Параметры".

    В табличной части отражается список документов, которые влияют на изменение статуса проекта.

    Закладка "Участники и окружение"

    Закладка "Участники и окружение" содержит внутренние закладки "Участники" и "Окружение".

    Внутренняя закладка "Участники"

    На данной внутренней закладке в табличной части "Роли и подразделения проекта" в качестве дополнительной информации по проекту можно ввести перечень подразделений с их проектными ролями.

  • N – номер по порядку, заполняется автоматически;
  • Роль – значение выбирается из справочника Роли трудовых ресурсов; 
  • Подразделение – значение выбирается из справочника Подразделения; 
  • Ответственный – значение выбирается из справочника Сотрудники; 
  • Комментарий – дополнительная информации о подразделениях с их проектными ролями.

    • В табличной части "Команда проекта" информативно выводятся назначенные на проект и проектные задачи трудовые ресурсы, сгруппированные по подразделениям.

    Внутренняя закладка "Окружение"

    На данной внутренней закладке в табличной части "Окружение проекта" в качестве дополнительной информации по проекту можно ввести перечень контрагентов с их проектными ролями.
  • N – номер по порядку, заполняется автоматически;
  • Роль – значение выбирается из справочника Роли трудовых ресурсов; 
  • Контрагент – значение выбирается из справочника Контрагенты; 
  • Ответственный – текстовое поле, в котором можно вручную указать ответственное лицо со стороны контрагента; 
  • Комментарий – дополнительная информация о контрагентах и их проектных ролях.

    • Закладка "Показатели"

    Основные показатели

    В табличной части "Основные показатели" отображаются автоматически рассчитанные показатели текущего проекта в соответствии с выбранной настройкой.

  • Настройка показателей для паспорта проекта – открывает перечень сохраненных настроек из обработки Панель руководителя и позволяет вывести в табличную часть набор показателей в соответствии с выбранной настройкой.

    • Важно! Настройка показателей для проекта указывается следующим образом:

  • При создании нового проекта реквизит "Настройка показателей для паспорта проекта" заполняется значением, указанным в Параметрах подсистемы PM (группа "Опции проектной модели");
  • При указании принадлежности записанного проекта какому-либо портфелю проектов (заполнении реквизита "Портфель проекта") значение реквизита "Настройка показателей для паспорта проекта" изменяется на настройку из указанного портфеля (при подтверждении использования функциональных опций из указанного портфеля). Если в указанном портфеле настройка показателей не задана, реквизит "Настройка показателей для паспорта проекта" заполняется значением, указанным в Параметрах подсистемы PM;
  • Значение реквизита "Настройка показателей для паспорта проекта" можно изменить вручную;
  • После очистки значения реквизита "Настройка показателей для паспорта проекта" и записи изменений в проекте, реквизит заполняется значением, указанным в Параметрах подсистемы PM.

    • Показатели со значениями, регистрируемыми вручную

    В табличной части "Показатели со значениями, регистрируемыми вручную" отображаются значения показателей по проекту, введенные пользователем с помощью документа Регистрация значений показателей проектов.

  • Кнопка Изменить показатели – открывает новый документ Регистрация значений показателей проектов и позволяет:
  • ввести первоначальное значение показатели по проекту, если значение еще не было зарегистрировано в системе; 
  • изменить существующее в системе значение показателя по проекту (при этом старое значение будет сохранено, новое значение будет введено еще одним документом).

    • В табличной части "Показатели со значениями, регистрируемыми вручную" будет отображаться последнее внесенное в систему значение показателя, которое является актуальным вплоть до ввода следующего значения показателя с более поздней датой документа.

    Закладка "Опции проектной модели"

    Учет доходов и расходов

    Доходы

  • Ведется бюджет доходов – данная опция определяет, будет ли вестись бюджет доходов по проекту. При указании опции, становится доступна закладка "План доходов" в документе Проектная задача;
  • Доходы по подразделениям – данная опция определяет, будет ли вестись бюджет доходов по проекту в разрезе подразделений. При указании опции, становится доступны табличные части "Распределение доходов" в документах Проектная задача и Регистрация доходов и расходов;
  • Доходы по объемам – при выборе данной опции будет возможно планировать выполнение объемов при планировании доходов. Если опция включена, в табличной части "Распределение доходов по подразделениям" в документах Проектная задача становятся доступны параметры "Способ привязки" и "Профиль / Дата привязки";
  • Доходы по натуральным показателям – при выборе данной опции будет возможно планировать выполнение объемов и планировать доходы в количественном выражении в разрезе номенклатуры при планировании выпуска субпродуктов. Планирование объемов при планировании доходов осуществляться не будет. Если опция включена, становится доступна табличная часть "Объемы" в документе Проектная задача и из табличной части "Распределение доходов по подразделениям" убираются параметры "Способ привязки" и "Профиль / Дата привязки".

    • Расходы

  • Ведется бюджет расходов – данная опция определяет, будет ли вестись бюджет расходов по проекту. При указании опции, становится доступна закладка "План расходов" в документе Проектная задача;
  • Расходы по подразделениям – данная опция определяет, будет ли вестись бюджет расходов по проекту в разрезе подразделений. При указании опции, становится доступны табличные части "Распределение расходов" в документах Проектная задача и Регистрация доходов и расходов;
  • Расходы по объемам – при выборе данной опции будет возможно планировать выполнение расходных объемов при планировании расходов. Если опция включена, в табличной части "Распределение расходов"в документах Проектная задача становятся доступны параметры "Способ привязки" и "Профиль / Дата привязки";
  • Расходы по натуральным показателям – при выборе данной опции будет возможно планировать выполнение расходных объемов и расходов в количественном выражении в разрезе номенклатуры при планировании потребностей материальных ресурсов. Планирование расходных объемов при планировании расходов осуществляться не будет. Если опция включена, из табличной части "Распределение расходов" в документах Проектная задача убираются параметры "Способ привязки" и "Профиль / Дата привязки".

    • Важно! При включении опции "Расходы по натуральным показателям" также включается и блокируется для изменения опция "Планировать затраты на материалы и оборудование". При отключенной опции "Расходы по натуральным показателям" опция "Планировать затраты на материалы и оборудование" изменяется без ограничений.

  • Настройка распределения БДР по умолчанию – настройка распределения БДР по подразделениям с учетом трудозатрат (элемент справочника Настройки распределения БДР), применяемая по умолчанию для обработки Распределение БДР при распределении доходов и расходов проектных задач проекта.

    • Учет ресурсов

  • Планировать трудозатраты по проекту – при указании опции, на закладке "Ресурсы" документа Проектная задача становятся доступны табличные части "Роли трудовых ресурсов" и "Исполнители";
  • Обязательно указывать подразделение – если опция включена, при планировании трудозатрат становится обязательным заполнение подразделений для указанных ролей трудовых ресурсов. Опция доступна при включении опции "Планировать трудозатраты по проекту";

    • Важно! Опция "Обязательно указывать подразделение" обязательна для включения при планировании и актуализации работ по проектам руководителем структурного подразделения (например, при помощи обработки Панель руководителя подразделения и документов Прогноз трудозатрат по ролям и Планирование трудозатрат по трудовым ресурсам).

  • Учитывать период регистрации норм стоимости при расчете трудозатрат Ролей и ТР:

  • Если опция включена, стоимости трудозатрат ролей / трудовых ресурсов по проектной задаче будут рассчитываться по нормам, указанным в документах Регистрация стоимости ресурса / Регистрация стоимости ресурсов с учетом дат этих документов и распределения загрузки ролей / трудовых ресурсов по проектной задаче. В проектных задачах на закладке "Ресурсы" → "Роли трудовых ресурсов" будет заблокирована кнопка Пересчитать по норме и вместо колонок "Стоимость", "Общая стоимость", "Внешняя стоимость" и "Общая Внешняя стоимость" табличной части будут отображены колонки "Стоимость (ср.)", "Общая стоимость", "Внешняя стоимость (ср.)" и "Общая Внешняя стоимость", недоступные для редактирования (значение рассчитывается автоматически);

  • Если опция выключена, стоимости трудозатрат ролей / трудовых ресурсов по проектной задаче будут рассчитываться по последним данным документов Регистрация стоимости ресурса / Регистрация стоимости ресурсов.

  • Норма стоимости – выбирается значение из справочника Нормы стоимости. Указанное значение автоматически подставляется в проектные задачи (закладка "Ресурсы" - "Роли трудовых ресурсов");

  • Внешняя норма стоимости – выбирается значение из справочника Нормы стоимости. Указанное значение автоматически подставляется в проектные задачи (закладка "Ресурсы" - "Роли трудовых ресурсов").

  • Планировать затраты на материалы и оборудование – при указании опции, на закладке "Ресурсы" документа Проектная задача становится доступна табличная часть "Материалы и оборудование";
  • Планировать дополнительные затраты по проектной задаче – при указании опции, на закладке "Ресурсы" документа Проектная задача становится доступна табличная часть "Доп. затраты".

    • Учет движения денежных средств

  • Ведется бюджет движения денежных средств – данная опция определяет, будет ли вестись бюджет движения денежных средств по проекту.

    • Прочие опции

  • Хранить в версиях проценты готовности, статусы и фактические сроки проектных задач – если опция включена, при создании новой версии проекта, в ней дополнительно будут сохраняться данные о процентах готовности, статусах и фактических сроках проектных задач. У таких версий будет установлен признак "Версия включает данные выполнения" (для Текущей версии установлен всегда, независимо от значения опции). Особенности хранения данных выполнения при работе с версиями проекта (копировании, обновлении, загрузке) описаны в обработке Управление версиями проекта.
  • Использовать аналитику "Контрагент" / "Трудовой ресурс" для собственных сил – опция позволяет указывать контрагента либо трудовой ресурс для собственных сил в реквизите "Исполнитель" в расшифровках табличных частей документа Проектная задача(при включенных в проекте опциях "Доходы/расходы по подразделениям, объемам, натуральным показателям"). 
  • Разрешить создание обсуждений без указания проектной задачи – опция позволяет создавать задания без привязки к конкретной проектной задаче. 
  • Разрешить списание часов на проектные задачи проекта в статусе "Остановлен"– опция позволяет Руководителю проекта списывать рабочее время, затраченное трудовыми ресурсами, для которых Руководитель проекта является владельцем, в документах Распределение рабочего времени за неделю, Табель учета рабочего времени и Прогноз трудозатрат по ролям на проектные задачи проекта, статус которого "Остановлен", вне зависимости от даты остановки проекта;

    • Важно!

  • Опция оказывает влияние как на заполнение документов Распределение рабочего времени за неделю, Табель учета рабочего времени и Прогноз трудозатрат по ролям, так и на возможность проведения этих документов в системе;
  • Списать фактические трудозатраты по проекту в статусе "Остановлен" можно строго до даты остановки проекта (дата документа Остановка проектных работ), дата остановки в период списания не входит.

  • Разрешить списание часов на проектные задачи проекта в статусе "Запланирован" и "Утвержден" – опция позволяет списывать рабочее время в документах Распределение рабочего времени за неделю, Табель учета рабочего времени и Прогноз трудозатрат по ролям на проектные задачи проекта, статус которого "Запланирован" или "Утвержден";
  • Запретить руководителю проектной задачи изменять сроки задач других руководителей – опция запрещает сохранение изменений в структуре проекта сотрудником, который является Руководителем проектных задач, но не является Руководителем проекта, если эти изменения влияют на сроки задач других сотрудников. 
  • Рассчитывать процент готовности при регистрации фактически выполненных объемов – опция позволяет рассчитывать проценты готовности проектных задач по план-фактным данным номенклатуры с признаком "Основной результат" из табличной части "Субпродукты" документа Проектная задача при проведении документов Регистрация фактически выполненного объема (в новых документах будет по умолчанию будет включена опция "Записывать процент готовности по доходным объемам", с возможностью отключить вручную).
  • Настройка дерева ключевых показателей – настройка дерева ключевых показателей, элемент справочника Настройки дерева ключевых показателей, в соответствии с которой будет отображаться Дерево ключевых показателей проекта. 
  • Настройка уровня планирования при расчете готовности проекта – уровень планирования трудозатрат для расчета процента готовности проектных задач при актуализации проекта документом Ручная актуализация проекта. Реквизит доступен только при включенной опции "Учитывать плановые трудозатраты при расчете процента готовности" в Параметрах подсистемы PM в группе "Основные параметры".

    • Автоматическое назначение руководителя проектной задачи

  • Автоматически назначать руководителя подразделения основной роли руководителем проектной задачи – опция позволяет при назначении ролей трудовых ресурсов на проектные задачи через документ Проектная задача и/или обработку Структура проекта автоматически назначать руководителем проектной задачи сотрудника, зарегистрированного в качестве руководителя подразделения, которому принадлежит роль, указанная в текущей проектной задаче как "Основная роль". Если опция включена и в проектной задаче указана основная роль, то блокируется возможность изменять руководителя проектной задачи вручную при помощи документа Изменение руководителя проектной задачи.

  • Автоматическая установка признака "Основная" при добавлении роли – опция позволяет при назначении ролей трудовых ресурсов на проектные задачи через документ Проектная задача и/или обработку Структура проекта автоматически устанавливать признак "Основная роль" для первой назначенной роли. Опция становится доступной только при включенной опции "Автоматически назначать руководителя подразделения основной роли руководителем проектной задачи".

    • Примечание. Если реквизит "Ед. изм. трудоемкости" не заполнен, в качестве единицы измерения трудозатрат используется "Час".

    Дополнительные настройки задачи

  • Наследовать значение поля "Объект" из задачи-родителя – если опция включена, у новых проектных задач и проектных задач, у которых изменяется уровень иерархии в структуре, значение реквизита "Объект" будет наследоваться от задачи-родителя. Наследование происходит по следующим принципам: 
  • У новых проектных задач реквизит "Объект" будет заполняться тем же значением, что и у задачи-родителя; 
  • Если у проектной задачи изменяется задача-родитель (через обработку Структура проекта или непосредственно в карточке проектной задачи) и реквизит "Объект" заполнен значением, отличным от значения этого реквизита у нового родителя, задается вопрос о замене значения реквизита в задаче; 
  • Если у проектной задачи изменяется задача-родитель (через обработку Структура проекта или непосредственно в карточке проектной задачи) и реквизит "Объект" не заполнен, значение автоматически наследуется от нового родителя; 
  • Если у задачи-родителя изменяется значение реквизита "Объект" и у подчиненных задач реквизит "Объект" заполнен значением, отличным от нового значения этого реквизита у задачи-родителя, задается вопрос о замене значения этого реквизита у всех подчиненных задач; 
  • Если у задачи-родителя изменяется значение реквизита "Объект" и у подчиненных задач реквизит "Объект" не заполнен, значение автоматически наследуется от задачи-родителя; 
  • При копировании задачи, значение реквизита "Объект" также копируется в новую задачу; 
  • При очищении у задачи реквизита "Родитель", задается вопрос об очищении реквизита "Объект".
  • Создавать задания при назначении ресурсов на проектную задачу – если опция включена, то при назначении трудовых ресурсов на проектную задачу автоматически создаются задания с видом "Поручение", связанные с задачей и адресованные назначенным исполнителям, что дает возможность последующего обмена сообщениями по проектной задаче между автором задания и исполнителем.

    • Примечание. Включение опции "Создавать задания при назначении ресурсов на проектную задачу" также может быть полезным, если в Параметрах подсистемы PM в группе "Настройки распределения рабочего времени" выбран вариант распределения "Только по поручениям".

  • Использовать значения для проектных задач в расчетах с показателями Go–Get–Freeze–Move: 
  • если опция включена, то в отчетах, где данные рассчитываются с учетом показателей Go–Get–Freeze–Move, значения данных показателей будут браться из проектной задачи. Если для проектной задачи значения Go–Get–Freeze–Move не заполнены, то в этом случае значения для расчета в отчетах будут браться из проекта;
  • если опция выключена, то в отчетах, где данные рассчитываются с учетом показателей Go–Get–Freeze–Move, значения для расчета в отчетах будут браться из проекта.
  • КнопкаТип продукта по умолчанию – позволяет переключать тип продукта между номенклатурой и проектной продукцией. Далее выбранный тип продукта по умолчанию устанавливается в плане выпуска на закладке "Объемы" документа Проектная задача.

    • Важно! Кнопка "Тип продукта по умолчанию" доступна только при включенной опции "Использовать проектную продукцию" в Параметрах подсистемы PM в группе "Проектная продукция".

    Трансляция в БДР

  • Включить затраты трудовых ресурсов в план расходов – информация о плановых трудозатратах будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане расходов.
  • Включить затраты материальных ресурсов в план расходов – информация о затратах на материальные ресурсы будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане расходов. 
  • Включить доп. затраты в план расходов – информация о дополнительных затратах проекта будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане расходов. 
  • Включить стоимость объемов в план доходов – информация о стоимости объемов будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане доходов. 

    • Важно! При одновременном использовании в проекте опций "Учитывать период регистрации норм стоимости при расчете трудозатрат Ролей и ТР" и "Включить затраты трудовых ресурсов в план расходов" необходимо выполнить следующие условия:

  • Для назначаемых ролей трудовых ресурсов должна быть зарегистрирована внутренняя нормированная стоимость документами Регистрация стоимости ресурса или Регистрация стоимости ресурсов. При этом, если стоимость ролей до этого никогда не регистрировалась, дата этих документов должна быть меньше (или равна) даты старта проекта.
  • В проектных задачах должна быть указана норма стоимости, по которой будет рассчитываться полная внутренняя стоимость привлечения роли трудового ресурса к выполнению проектной задачи (реквизит "Норма стоимости"). Автоматически заполняется значением соответствующего реквизита из карточки проекта / Портфеля проектов / Параметров подсистемы PM.
  • Указать распределение стоимости по статьям затрат в карточке роли (см. Роли трудовых ресурсов).
  • В статьях затрат, по которым распределяется стоимость роли, заполнить реквизиты для отражения трудозатрат (см. Статьи затрат по проектам).

  • Реквизит "Схема оплаты по умолчанию для доходов" в Параметрах подсистемы PM в группе "Опции проектной модели".

  • Договор, указанный в строке расходов;
  • Контрагент, указанный в строке расходов;
  • Статья затрат, указанная в строке расходов;
  • Реквизит "Схема оплаты по умолчанию для расходов" в проектной задаче;
  • Реквизит "Схема оплаты по умолчанию для расходов" в карточке проекта на закладке "Дополнительно".
  • Реквизит "Схема оплаты по умолчанию для расходов" в Параметрах подсистемы PM в группе "Опции проектной модели".
