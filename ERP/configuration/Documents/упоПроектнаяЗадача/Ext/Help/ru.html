Документ Проектная задача



Если в справке напротив поля или элемента интерфейса есть иконка, то элемент доступен только в приложении "1С:PM Управление проектами КОРП" (1С:PM КОРП).

Назначение

Документ "Проектная задача" предназначен для ввода в систему планируемых параметров и характеристик проектных задач.

Форма объекта

На командной панели расположены кнопки для работы с документом:

  • Кнопка Провести и закрыть – сохраняет измененные данные в документе, формирует движения по регистрам системы и закрывает форму документа.
  • Кнопка Записать – сохраняет измененные данные в документе.
  • Кнопка Провести – сохраняет измененные данные в документе и формирует движения по регистрам системы.
  • Кнопка Структура проекта – открывает обработку Структура проекта (с позиционированием на проектной задаче) для ввода плана работ по проекту.
  • Кнопка Риски – открывает справочник Риски проектов с установленным отбором по текущему проекту и проектной задаче.
  • Кнопка Хозяйственные операции задачи – открывает обработку Хозяйственные операции проекта с отбором по текущей проектной задаче.
  • Кнопка Задания → Открыть задания – открывает перечень заданий по текущей проектной задаче.
  • Кнопка Задания → Открыть проектные решения – открывает перечень проектных решений по текущей проектной задаче.
  • Кнопка Задания → Открыть задания на планирование – открывает перечень заданий на планирование (с признаком "Задание подразделению" и видом задания "Задание на планирование") по текущей проектной задаче.
  • Кнопка Задания → Открыть задания на прогноз – открывает перечень заданий на прогноз (с признаком "Задание подразделению" и видом задания "Задание на прогноз") по текущей проектной задаче.
  • Кнопка Отчеты – открывает перечень отчетов, которые можно сформировать по текущей проектной задаче.
  • Кнопка Отчеты → Движения документа – открывает отчет о движениях документа по регистрам системы, если документ "Проектная задача" был проведен.
  • Кнопка Создать на основании – позволяет создать на основании выбранной проектной задачи некоторые виды документов, связанные с регистрацией фактических данных по проекту, актуализацией данных проекта и т.п. В созданных таким образом документах реквизиты "Проект" и "Проектная задача" будет заполняться автоматически текущими значениями.
  • Кнопка Еще → Дополнительные сведения – открывает форму Редактирование дополнительных сведений.
  • Кнопка Еще → Изменить состав дополнительных реквизитов – открывает справочник Наборы дополнительных реквизитов и сведений.

    • Важно! Кнопки Дополнительные сведения и Изменить состав дополнительных реквизитов доступны только если в настройках информационной базы включено использование дополнительных реквизитов и сведений (установлен флаг "Дополнительные реквизиты и сведения" в разделе "Администрирование" → "Общие настройки" → группа "Дополнительные реквизиты и сведения").

    К основным реквизитам документа "Проектная задача" относятся следующие:

  • Номер документа — формируется автоматически.
  • Дата — формируется автоматически, по умолчанию в реквизит подставляется текущая дата.
  • Проект — проект, к которому принадлежит проектная задача, элемент справочника Проекты.

    • Реквизиты и табличные части документа "Проектная задача" разнесены по нескольким закладкам.

    Закладка "Параметры"

    На этой закладке представлены основные параметры проектной задачи.

  • Название проектной задачи — текстовое наименование проектной задачи.
  • Вид операции — указывается вид операции задачи. Значение выбирается из списка значений справочника Виды операций.
  • Объект — указывается объект, к которому относится текущая задача. Значение выбирается из списка значений справочника Объекты.
  • Статус — выводится текущий процент готовности проектной задачи и ее статус ("Запланирована" / "Выполняется" / "Завершена").
  • Руководитель задачи — выводится текущий руководитель проектной задачи (по умолчанию – руководитель проекта).

    • Детализация графика

  • Подчиненный проект — указывается подчиненный проект, который детализирует проектную задачу по составу и срокам работ. Значение выбирается из списка значений справочника Проекты.

    • Место задачи в структуре декомпозиции работ

  • Родитель — проектная задача с типом "Этап", которой в рамках СДР подчинена текущая проектная задача. Если задача-родитель не выбрана, это означает, что текущая проектная задача находится на самом верхнем уровне СДР. Изменение задачи-родителя производится посредством кнопки Изменить.
  • СДР-код задачи — СДР-код формируется автоматически в момент проведения документа, пользователь не имеет возможности изменить этот реквизит.
  • Код ПД — код проектного документа, проставляется пользователем вручную.

    • Тип проектной задачи

  • Тип проектной задачи — реквизит указывает, к какому из возможных типов принадлежит проектная задача:
  • Проектная задача является этапом или подэтапом проекта — такая проектная задача является контейнером для проектных задач более низких уровней декомпозиции.
  • Проектная задача является моделью пакета работ — проектная задача, которая находится на нижнем уровне декомпозиции. Содержит данные о трудозатратах и выполняемых работах. Эти данные вводятся непосредственно в документ (на закладке "Ресурсы").
  • Проектная задача является вехой — проектная задача, которая имеет нулевую длительность и не содержит данных о трудозатратах и выполняемых работах.

    • Важно! Тип проектной задачи можно изменять только в том случае, если для проектной задачи в систему еще не было введено никаких данных, специфичных для конкретного типа.

  • Проектная задача является актируемой — дополнительный аналитический признак, позволяющий отделять актируемые задачи в отчетах. В обработке Структура проекта показатели "Начало по ДП", "Окончание по ДП" отображаются только в том случае, если у проектной задачи установлен данный признак.
  • Не выводить в статус-отчет — опция отвечает за отображение проектной задачи в документе Статус-отчет по проекту. По умолчанию, опция отключена для всех проектных задач, т.е. задачи выводятся в документ. При установке данной опции у задачи с типом "Этап", подчиненные ей задачи также не будут выводиться в статус-отчет.
  • Выводить в сводный статус-отчет — опция отвечает за отображение проектной задачи в документе Сводный статус-отчет по проектам. По умолчанию, опция включена для всех проектных задач с типом "Этап". При отключении данной опции у задачи с типом "Этап", подчиненные ей задачи также не будут выводиться в сводный статус-отчет.
  • Задача отменена Восстановить — надпись и команда выводятся в случае, если проектная задача отменена. Задача отменяется при нажатии на кнопку Delete или выборе команды "Отменить" в подменю "Еще" в обработке Структура проекта. Отмененная задача не отображается в структуре проекта и, если по задаче есть только плановые данные, не выводится в отчеты. Если по отмененной задаче есть фактические данные, она выводится в отчеты с префиксом <ОТМЕНЕНА>. Для восстановления задачи необходимо нажать кнопку Восстановить. 

    • Важно! Отмененную задачу нельзя восстановить, если ее задача-родитель также отменена. Восстановление задач следует производить по иерархии "сверху вниз".

    Информация о копировании

    Заполняется у задач, которые были перенесены (скопированы) в сводный проект документом Копирование задач в сводный проект.

  • Скопирована в сводный из задачи — ссылка на оригинальную проектную задачу;
  • Из проекта — ссылка на проект, в который входит оригинальная проектная задача;
  • Документ копирования — ссылка на документ Копирование задач в сводный проект, которым производилось копирование проектной задачи.

    • Закладка "Сроки задачи"

    На этой закладке представлены реквизиты документа и кнопки, при помощи которых производится управление сроками проектной задачи.

    Планируемые сроки проектной задачи

  • Режим ввода сроков проектной задачи — реквизит указывает, каким именно образом будут вводиться в систему сроки проектной задачи:
  • Ручной ввод — позволяет вручную указать произвольные сроки проектной задачи, без учета связей с задачами-предшественниками.
  • При расчете сроков проекта — сроки проектной задачи рассчитываются автоматически, исходя из длительности задачи и связей с задачами-предшественниками.
  • Начало работ:
  • колонка Ручной ввод – дата начала проектной задачи, реквизит доступен для редактирования только в режиме ручного ввода сроков.
  • колонка Текущий план – актуальный (текущий) плановый срок начала проектной задачи в соответствии с утвержденным календарным планом проекта.
  • кнопка-индикатор конфликта сроков – отображается слева от даты текущего плана, если длительность проектной задачи превышает длительность задачи-родителя (этапа). При нажатии на команду выводится сообщение с предупреждением.
  • колонка Не раньше – дата раннего старта проектной задачи, рассчитывается автоматически для критического пути;
  • колонка Не позже – дата позднего старта проектной задачи, рассчитывается автоматически для критического пути.
  • Завершение работ:
  • колонка Ручной ввод – дата завершения проектной задачи, реквизит доступен для редактирования только в режиме ручного ввода сроков;
  • колонка Текущий план – актуальный (текущий) плановый срок завершения проектной задачи в соответствии с утвержденным календарным планом проекта.
  • кнопка-индикатор конфликта сроков – отображается слева от даты текущего плана, если длительность проектной задачи превышает длительность задачи-родителя (этапа). При нажатии на команду выводится сообщение с предупреждением.
  • колонка Не раньше – дата раннего финиша проектной задачи, рассчитывается автоматически для критического пути;
  • колонка Не позже – дата позднего старта проектной задачи, рассчитывается автоматически для критического пути.

    • Примечание. Если дата начала в колонке Ручной ввод совпадает с ранним и поздним стартом, а дата окончания в колонке Ручной ввод совпадает с ранним и поздним финишем, то это значит, что проектная задача находится на критическом пути. На диаграмме Ганта такие проектные задачи можно выделить красным цветом при включении кнопки Показывать критический путь.

  • Крайний срок — максимально допустимый срок завершения проектной задачи. Реквизит используется при автоматическом расчете календарного плана проекта;
  • кнопка-индикатор конфликта сроков – отображается справа от даты крайнего срока, если длительность проектной задачи превышает длительность задачи-родителя (этапа). При нажатии на команду выводится сообщение с предупреждением.

    • Общая календарная длительность

  • Кнопка Рассчитать длительность → По ролям — рассчитывает длительность проектной задачи по плановым трудозатратам ролей. Если в проектной задаче запланированы трудозатраты только по предварительному уровню планирования, то длительность будет рассчитываться делением максимального значения плановых трудозатрат по уровню планирования "Предварительный" на количество часов в единице измерения длительности проектной задачи. Если в проектной задаче есть плановые трудозатраты по окончательному уровню планирования, то длительность будет рассчитываться делением максимального значения плановых трудозатрат по уровню планирования "Окончательный" на количество часов в единице измерения длительности проектной задачи.
  • Кнопка Рассчитать длительность → По субпродуктам — рассчитывает длительность проектной задачи по данным закладки "Объемы". Если для субпродукта указаны количество и скорость (объем/день), то делением количества на скорость (объем/день) будет получена длительность. Если указано несколько субпродуктов и их скорость (объем/день), то в качестве длительности проектной задачи будет использовано максимальное значение из рассчитанных по субпродуктам.
  • Длительность — общая календарная длительность проектной задачи.

    • Примечание. При расчете сроков проектной задачи её длительность, указанная в выбранных единицах измерения (например, днях или неделях), переводится в часы. Полученное значение округляется до целого часа, после чего используется при вычислении сроков проектной задачи.

  • Ед. изм. — элемент справочника Единицы измерения времени. Реквизит указывает, в какой именно единице измерения представлена общая календарная длительность.
  • Календарь задачи — календарь, используемый для расчета длительности проектной задачи. Заполняется подбором из справочника Рабочие календари, в том случае, если для расчета сроков задачи планируется использовать календарь отличный от календаря проекта.
  • Длительность без учета календаря проекта или задачи — если флаг установлен, то длительность проектной задачи при расчете сроков проектной задачи будет вычисляться без учета рабочего календаря проекта или календаря проектной задачи, из расчета 168 часов в неделю (24/7). Если флаг не установлен, то, наоборот, при расчете длительность будет вычисляться по календарю проекта (задается документом Регистрация проекта) или, если заполнен реквизит "Календарь задачи", по календарю проектной задачи. Это означает, что при расчете сроков проектной задачи по длительности будут приниматься во внимание только те дни, которые определены как рабочие календарем проекта или проектной задачи.

    • Важно! При включении опции "Длительность без учета календаря проекта или задачи" в качестве единицы измерения длительности проектной задачи устанавливается значение "Сутки" (без возможности редактирования) и производится пересчет длительности задачи.

  • Расчетная дата завершения задачи — дата завершения проектной задачи, рассчитанная с учетом длительности, календаря задачи (если реквизит не заполнен, используется календарь проекта) и опции "Длительность без учета календаря проекта или задачи".
  • Сумма санкций за день задержки — пользователь вручную может указать сумму санкций за каждый день срыва сроков работ по этапу проекта или по проектной задаче. Значение может быть указано как со знаком плюс, так и со знаком минус, это повлияет на отображение данных в поле "Сумма санкций" в обработке Структура проекта.

    • Также на этой закладке представлена информация о сроках проектной задачи по текущему (актуальному) календарному плану проекта. В случае если между сроками проектной задачи и сроками других проектных задач возникает противоречие (например, дата завершения задачи-родителя оказывается раньше по времени, чем дата завершения подчиненной задачи), информацию о конфликте сроков можно вывести на форму нажав на кнопку, расположенную рядом с реквизитом "Начало работ".

    Прогнозные сроки

  • Дата начала, прогноз — прогнозная дата начала проектной задачи, устанавливается вручную в обработке Структура проекта либо в проектной задаче.
  • Дата завершения, прогноз — прогнозная дата завершения проектной задачи, устанавливается вручную в обработке Структура проекта либо в проектной задаче.
  • Статус сроков — индикатор отставания фактического выполнения проектной задачи по срокам. Статус сроков устанавливается вручную в обработке Структура проекта и проектной задаче, либо рассчитывается на основании плановых сроков и процента готовности проектной задачи в обработке Структура проекта. Возможные значения:
  • План;
  • Выполнено;
  • По графику;
  • Задержка;
  • Срыв.

    • Закладка "Предусловия"

    На этой закладке представлены предусловия проектной задачи – список проектных задач, сроки выполнения которых взаимосвязаны со сроками выполнения текущей проектной задачи. По сути, предусловия отражают связи между разными элементами данного проекта, а также связи элементов данного проекта с элементами других проектов.

  • Кнопка Подобрать — открывает универсальную форму подбора табличной части.
  • Кнопка Добавить связь с задачей другого проекта — открывает форму выбора проектной задачи для установки связи с задачей другого проекта.

    • В табличной части указываются следующие значения:

  • Между проектами — признак, указывающий на связь между разными проектами. Устанавливается автоматически, только для задачи-предшественника, выбранной из другого проекта.
  • Проект — проект, из которого была выбрана задача-предшественник. Заполняется автоматически, только для задачи-предшественника, выбранной из другого проекта.
  • СДР — код СДР задачи–предшественника. Заполняется автоматически при выборе предшественника.
  • Предшественник — задача, с которой будет установлен связь у текущей задачи.
  • Тип связи — пользователь выбирает одну из четырех видов связи:
  • Окончание–начало — выполнение текущей задачи начнется после завершения предыдущей;
  • Начало–начало — выполнение текущей задачи начнется одновременно с предыдущей;
  • Окончание–окончание — выполнение текущей задачи закончится одновременно с предыдущей;

  • Пользователь вручную распределяет данные по выпуску по месяцам, количество которых зависит от сроков проектной задачи. При этом заполняются колонки "Количество" и "Сумма" в каждом месяце.

  • перетаскивать нераспределенное количество/сумму из колонки "Не распределено" в колонки выбранного месяца;
  • выбирать количество/сумму в поле определенного месяца и перетаскивать данные на другой месяц;
  • редактировать количество/сумму плана в колонке выбранного месяца.

  • Специальность – роль трудового ресурса-исполнителя. По умолчанию заполняется из карточки проекта, реквизит "Роль доходов по умолчанию" с закладки "Значения по умолчанию";

  • Исполнитель – элемент справочника Контрагенты/Трудовые ресурсы:
  • подрядчик, если установлен признак "Субподряд";
  • относящийся к собственным силам, если установлен признак "Собственные силы" и в опциях проектной модели включена опция "Использовать аналитику "Контрагент" / "Трудовой ресурс" для собственных сил";
  • Договор – договор с контрагентом;
  • % ТРЗ – доля распределения трудоемкости между ролями трудовых ресурсов, заполняется только при производстве проектной продукции;
  • Количество – количество плановых объемов;
  • Норма – распределенная норма трудозатрат между ролями трудовых ресурсов. Рассчитывается по формуле: Норма (общая) * %ТРЗ. Заполняется только при производстве проектной продукции;
  • Коэф. – индивидуальный коэффициент сложности производства проектной продукции, для номенклатуры не используется;
  • ТРЗ – количество трудозатрат, планируемых для производства проектной продукции для определенной роли трудового ресурса. Рассчитывается по формуле: Норма (по роли) * Коэф. (по роли), для номенклатуры не используется;
  • Сумма – сумма плановых объемов в денежном выражении;
  • Способ привязки – способ привязки плановых объемов к датам:
  • По профилю распределения – в соответствии с настройкой профиля распределения, указанного в поле "Профиль / Дата привязки");
  • К конкретной дате – в соответствии с датой, указанной в поле "Профиль / Дата привязки");
  • Вручную, по месяцам – при выборе данного варианта появляются дополнительные колонки справа для ручного распределения количества и суммы по месяцам);
  • Профиль / Дата привязки – профиль распределения по датам или конкретные даты.
