Параметры подсистемы PM



Если в справке напротив поля или элемента интерфейса есть иконка, то элемент доступен только в приложении "1С:PM Управление проектами КОРП" (1С:PM КОРП).


Если в справке напротив поля или элемента интерфейса есть иконка, то элемент доступен только в приложении "1С:ERP+PM Управление проектной организацией 2" (1С:ERP+PM).

Назначение

Форма предназначена для управления константами (параметрами) информационной базы на основе конфигурации. Через механизм констант реализуется управление общими (глобальными) настройками информационной базы.

Реквизиты формы

Каждый из реквизитов формы связан с одноименной константой информационной базы. Константы делятся на две группы: управляемые пользователем (пользователь может модифицировать значение константы) и служебные (пользователь не может модифицировать значение константы). Служебные константы выведены на форму в режиме "только чтение".

Управляемые пользователем константы

К константам, значение которых может модифицировать пользователь, относятся:

Группа "Основные параметры"

  • Отключить разграничение доступа пользователя к проектным документам – константа указывает, нужно ли при проведении документов Проектная задача или редактировании структуры проекта проверять правомочность выполнения операции текущим пользователем с точки зрения проектной и функциональной иерархии сотрудников предприятия, а также учитывать статусы проектных задач ("Завершена" / "Закрыта").
  • Если опция отключена (флаг снят), то:
  • Доступ к редактированию структуры проекта и соответствующих проектных задач будут иметь только те сотрудники, которые играют соответствующую роль в проекте (например, проектную задачу сможет провести только руководитель проекта и/или этой задачи, и т.д.); для всех остальных пользователей формы структуры проекта и проектных задач будут открываться в режиме "только чтение".
  • Для проектных задач в статусе "Завершена" будет запрещено создание подчиненных задач и редактирование плановых данных.
  • Для проектных задач в статусе "Закрыта" будет запрещено создание подчиненных задач и редактирование плановых данных.
  • Работать с версиями проекта может только пользователь, являющийся диспетчером руководителя выбранного проекта.
  • Если опция включена (флаг установлен), то:
  • При изменении структуры проекта и проектных задач никаких проверок производиться не будет.
  • Для проектных задач в статусе "Завершена" будет разрешено создание подчиненных задач и редактирование плановых данных.
  • Для проектных задач в статусе "Закрыта" будет разрешено создание подчиненных задач и редактирование плановых данных, если не установлен флаг "Строгий контроль изменения закрытых этапов".
  • При работе с версиями проекта будет производиться только проверка доступа к обработке Управление версиями проекта и на право работы с Договорной и Базовой версиями проекта, проверка на отношение пользователя к проекту производиться не будет.
  • Строгий контроль изменения закрытых этапов – опция включает блокировку, для проектных задач в статусе "Закрыта", следующих возможностей:
  • создание подчиненных ПЗ (заблокировано по умолчанию при отключенной опции "Отключить разграничение доступа пользователя к проектным документам");
  • изменение плановых данных (заблокировано по умолчанию при отключенной опции "Отключить разграничение доступа пользователя к проектным документам");
  • изменение / ввод фактических данных;
  • отражение данных о рабочем времени.
  • Отложенный расчет сроков проектов – используется для настройки пересчета сроков проектов после выполнения действий, влияющих на сроки проектных задач.
  • Расписание – регламентное задание Расчет сроков проектов.
  • Очередь – регистр сведений Очередь расчета сроков проектов.
  • Автоматический расчет сроков связанных проектов – если опция включена, после установки связей между задачами разных проектов сроки всех связанных проектов будут пересчитываться автоматически при помощи регламентного задания "Расчет сроков проектов". Неотработанные события хранятся в регистре сведений Очередь расчета сроков проектов. Очередь расчета сроков проектов.
  • Отложенное отражение плановых трудозатрат задач – если опция включена, то при планировании трудозатрат проектных задач, движения по регистрам Актуальные планы трудозатрат (Текущая версия) и Актуальные планы трудозатрат по дням (Текущая версия) формируются регламентным заданием "Отражение плановых трудозатрат задач" в соответствии с заданным расписанием. Если опция отключена, движения по регистрам формируются сразу при записи данных. Данная опция служит для удобства работы с обработкой Структура проекта при назначении трудовых ресурсов на проектную задачу (сокращается время ожидания при записи данных). Очередь неотраженных плановых трудозатрат задач хранится в регистре сведений Очередь отражения плановых трудозатрат задач.
  • Расписание – регламентное задание Отражение плановых трудозатрат задач.
  • Очередь - регистр сведений Очередь отражения плановых трудозатрат задач.
  • Создавать задания при назначении ресурсов на проектную задачу – опция указывает, нужно ли по умолчанию включать опцию "Создавать задания при назначении ресурсов на проектную задачу" для новых элементов справочника Проекты (флаг "Создавать задания при назначении ресурсов на проектную задачу" на закладке "Дополнительно" в карточке проекта). Если опция в проекте включена, то при назначении трудовых ресурсов на проектную задачу автоматически создаются задания с видом "Поручение", связанные с задачей и адресованные назначенным исполнителям, что дает возможность последующего обмена сообщениями по проектной задаче между автором задания и исполнителем.
  • Отложенная синхронизация поручений с проектными задачами – если опция включена, то (при включенной в карточке проекта опции "Создавать задания при назначении ресурсов на проектную задачу") при назначении трудовых ресурсов на проектную задачу поручения будут формироваться регламентным заданием "Синхронизация поручений и проектных задач" в соответствии с заданным расписанием. Если опция отключена, поручения будут создаваться сразу после назначения трудовых ресурсов на проектную задачу. Очередь проектных задач, по которых ожидается создание поручений, хранится в регистре сведений Очередь синхронизации поручений задач.
  • Расписание – регламентное задание Синхронизация поручений и проектных задач.
  • Очередь – регистр сведений Очередь синхронизации поручений задач.
  • Дата актуальности – граница для расчета показателей, связанных с ФОТ и EVA, в обработках Структура проекта и Панель руководителя. Для получения фактических трудозатрат в показателях ФОТ используются данные с даты актуальности. Для получения плановых данных по расходам в показателях EVA используются данные по дату актуальности.

    • Настройки валюты

  • Валюта управленческого учета — в этой валюте ведется управленческий учет. В ней хранятся суммы в регистрах наряду с суммами в валюте документа.

    • Важно! Валюты учета можно изменять, только пока не введены документы.

    Настройка актуализации проекта

  • Автоматически рассчитывать процент готовности этапов проекта – если опция включена, при актуализации проекта документом Ручная актуализация проекта проценты готовности этапов будут рассчитываться автоматически по процентам готовности вложенных в этап проектных задач. Если опция отключена, проценты готовности этапов при актуализации нужно будет рассчитывать по длительности или трудозатратам при помощи соответствующих кнопок, либо указывать вручную.
  • Учитывать плановые трудозатраты проектной задачи при расчете процента готовности этапа – опция указывает на необходимость учитывать плановые трудозатраты проектных задач при расчете процентов готовности этапов. Если опция включена, то становятся доступны опция "Использовать длительность, если по задаче нет плана трудозатрат" и реквизит "Уровень планирования при расчете готовности", процент готовности этапов рассчитывается по процентам готовности вложенных задач и плановым трудозатратам (если есть) выбранного уровня планирования. Если опция выключена – опция и реквизит недоступны, а процент готовности этапов рассчитывается по процентам готовности вложенных задач и длительности.
  • Использовать длительность, если по задаче нет плана трудозатрат – опция отвечает за влияние проектных задач без плановых трудозатрат на указанном в реквизите "Уровень планирования при расчете готовности" уровне на автоматически рассчитываемый процент готовности этапа. Если опция включена, задачи без плановых трудозатрат будут влиять на процент готовности этапа, но при расчетах будет использоваться длительность этих задач (в часах). Если опция отключена, задачи без плановых трудозатрат не будут оказывать влияние на процент готовности этапа. Опция включается автоматически при включении опции "Учитывать плановые трудозатраты проектной задачи при расчете процента готовности этапа".
  • Уровень планирования при расчете готовности – уровень планирования трудозатрат для расчета процентов готовности этапов. Реквизит доступен только при включенной опции "Учитывать плановые трудозатраты проектной задачи при расчете процента готовности этапа".

    Группа "Значения по умолчанию"

    Используются в документе Проектная задача для заполнения по умолчанию при планировании доходов и расходов.

    Значения заполнения бюджетов

  • Ставка НДС по умолчанию – ставка НДС, используемая по умолчанию:
  • при заполнении нового элемента справочника Настройки распределения БДР;
  • при выделении сумм НДС с учетом порядка применения ставки НДС, описанного в справочной информации документов:
  • Проектная задача;
  • Регистрация доходов и расходов;
  • Регистрация фактического выполненного объема;
  • Регистрация затрат материальных ресурсов.

    • Доходы

  • Статья доходов – элемент справочника Статьи доходов по проектам;
  • Роль доходов – элемент справочника Роли трудовых ресурсов;
  • Подразделение доходов – элемент справочника Подразделения;
  • Профиль доходов – элемент справочника Профили распределения доходов и расходов;
  • Натуральный показатель доходов – элемент справочника Номенклатура.

    • Расходы

  • Статья затрат – элемент справочника Статьи затрат по проектам;
  • Роль затрат – элемент справочника Роли трудовых ресурсов;
  • Подразделение затрат – элемент справочника Подразделения;
  • Профиль расходов – элемент справочника Профили распределения доходов и расходов;
  • Натуральный показатель расходов – элемент справочника Номенклатура.

    • Настройки трансляции

    Трансляция в БДР

  • Включить затраты трудовых ресурсов в план расходов – информация о плановых трудозатратах будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане расходов.
  • Включить затраты материальных ресурсов в план расходов – информация о плановых затратах на материальные ресурсы будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане расходов.
  • Включить доп. затраты в план расходов – информация о плановых дополнительных затратах будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане расходов.
  • Включить стоимость объемов в план доходов – информация о плановой стоимости объемов будет автоматически попадать в план БДР проекта без дублирования пользователем информации в плане доходов.

    • Важно! При одновременном использовании опций "Учитывать период регистрации норм стоимости при расчете трудозатрат Ролей и ТР" и "Включить затраты трудовых ресурсов в план расходов" необходимо выполнить следующие условия:

  • Для ролей трудовых ресурсов зарегистрировать внутреннюю нормированную стоимость документами Регистрация стоимости ресурса или Регистрация стоимости ресурсов. При этом следует помнить, что стоимость роли будет действовать с даты создаваемого документа.
  • В проектных задачах проектов должна быть указана норма стоимости, по которой будет рассчитываться полная внутренняя стоимость привлечения роли трудового ресурса к выполнению проектной задачи (реквизит "Норма стоимости"). Автоматически заполняется значением реквизита "Норма стоимости" из Проекта / Портфеля проектов / Параметров подсистемы PM.
  • Указать распределение стоимости по статьям затрат в карточке роли (см. Роли трудовых ресурсов).
  • В статьях затрат, по которым распределяется стоимость роли, заполнить реквизиты для отражения трудозатрат (см. Статьи затрат по проектам).

    • Трансляция в ДДС

  • Включить план доходов в БДДС – данные плана доходов будут автоматически включаться в план БДДС.
  • Схема оплаты по умолчанию для доходов – схема оплаты для переноса строк плана доходов в план БДДС, элемент справочника Схемы оплаты.
  • Включить план расходов в БДДС – данные плана расходов будут автоматически включаться в план БДДС.
  • Схема оплаты по умолчанию для расходов – схема оплаты для переноса строк плана расходов в план БДДС, элемент справочника Схемы оплаты.
  • Проектная задача по умолчанию для БДР – проектная задача для заполнения по умолчанию в документах Синхронизация фактических доходов и расходов при загрузке данных из "1С:Бухгалтерия предприятия", если в дебетовых оборотах отсутствует субконто "Направление деятельности".

    • Календари, единицы измерения

  •  Рабочий календарь – рабочий календарь по умолчанию для заполнения документа Регистрация проекта.
  • Ед. изм. длительности – значение выбирается из справочника Единицы измерения времени и используется как единица измерения длительности проектной задачи по умолчанию:
  • в обработке Структура проекта при добавлении новой задачи;
  • в обработке Импорт из MS Project при загрузке календарного плана проекта.
  • Ед. изм. трудоемкости – значение выбирается из справочника Единицы измерения времени и используется как единица измерения трудоемкости роли трудового ресурса при добавлении ролей в проектную задачу.

    • Дополнительные настройки

  •  Наследовать значение поля "Объект" из задачи-родителя – если опция включена, у новых проектных задач и проектных задач, у которых изменяется уровень иерархии в структуре, значение реквизита "Объект" будет наследоваться от задачи-родителя. Наследование происходит по следующим принципам: 
  • У новых проектных задач реквизит "Объект" будет заполняться тем же значением, что и у задачи-родителя; 
  • Если у проектной задачи изменяется задача-родитель (через обработку Структура проектаили непосредственно в карточке проектной задачи) и реквизит "Объект" заполнен значением, отличным от значения этого реквизита у нового родителя, задается вопрос о замене значения реквизита в задаче; 
  • Если у проектной задачи изменяется задача-родитель (через обработку Структура проектаили непосредственно в карточке проектной задачи) и реквизит "Объект" не заполнен, значение автоматически наследуется от нового родителя; 
  • Если у задачи-родителя изменяется значение реквизита "Объект" и у подчиненных задач реквизит "Объект" заполнен значением, отличным от нового значения этого реквизита у задачи-родителя, задается вопрос о замене значения этого реквизита у всех подчиненных задач; 
  • Если у задачи-родителя изменяется значение реквизита "Объект" и у подчиненных задач реквизит "Объект" не заполнен, значение автоматически наследуется от задачи-родителя; 
  • При копировании задачи, значение реквизита "Объект" также копируется в новую задачу; 
  • При очищении у задачи реквизита "Родитель", задается вопрос об очищении реквизита "Объект".
  • Вид операции общий – константа влияет на заполнение табличной части в обработке Моделирование эффективности проекта. По указанному в параметрах информационной базы общему виду операции с закладки "Компетенции" элемента справочника Контрагенты в обработке будут заполняться значения реквизитов "Стоимость дня", "Выработка", "% на управление", "Вероятность срыва,%", "Увеличение длительности, %". Константа доступна при включении использования контура "Нормирование и проектные решения" (группа "Нормирование и проектные решения").
  • Портфель заказов – портфель проектов, используемый для отбора проектов на форме Рабочего стола. Если в настройке указан портфель проектов, то на Рабочем столе по команде "Портфель заказов" будут выводиться проекты по текущему портфелю. Если портфель не указан, по команде "Портфель заказов" будет выводиться перечень проектов с незаполненным реквизитом "Портфель проектов".
  • Ед. изм. времени для расчета показателя структуры проекта "Объемы (V) план, ч" – единица измерения, по которой будет происходить отбор данных плановых трудозатрат по доходным и расходным объемам для показателя "Объемы (V) план, ч" обработки Структура проекта. Ожидается указание единицы измерения "Час". Если константа не заполнена, показатель в структуре проекта будет пустой. Описание показателя "Объемы (V) план, ч" см. в справке к обработке.

    • Группа "Опции проектной модели"


    Функциональные опции, указанные в параметрах информационной базы, будут являться значениями по умолчанию для всех создаваемых элементов справочников Портфели проектов и Проекты.

    Учет доходов и расходов

    Доходы

  • Ведется бюджет доходов – опция определяет, будет ли вестись бюджет доходов по проекту. При указании опции, становится доступна закладка "План доходов" в документе Проектная задача. 
  • Доходы по подразделениям – опция определяет, будет ли вестись бюджет доходов по проекту в разрезе подразделений. При указании опции, становится доступны табличные части "Распределение доходов" в документах Проектная задача и Регистрация доходов и расходов. 
  • Доходы по объемам – при выборе данной опции будет возможно планировать выполнение объемов при планировании доходов. Если опция включена, в табличной части "Распределение доходов" в документах Проектная задача становятся доступны параметры "Способ привязки" и "Профиль / Дата привязки". 
  • Доходы по натуральным показателям – при выборе данной опции будет возможно планировать выполнение объемов и планировать доходы в количественном выражении в разрезе номенклатуры при планировании выпуска субпродуктов. Планирование объемов при планировании доходов осуществляться не будет. Если опция включена, становится доступна табличная часть "Объемы" в документе Проектная задача и из табличной части "Распределение доходов по подразделениям" убираются параметры "Способ привязки" и "Профиль / Дата привязки".

    • Расходы

  • Ведется бюджет расходов – опция определяет, будет ли вестись бюджет расходов по проекту. При указании опции, становится доступна закладка "План расходов" в документе Проектная задача. 
  • Расходы по подразделениям – опция определяет, будет ли вестись бюджет расходов по проекту в разрезе подразделений. При указании опции, становится доступны табличные части "Распределение расходов" в документах Проектная задача и Регистрация доходов и расходов. 
  • Расходы по объемам – опция определяет, будет ли возможно планировать выполнение расходных объемов при планировании расходов. Если опция включена, в табличной части "Распределение расходов" в документах Проектная задача становятся доступны параметры "Способ привязки" и "Профиль / Дата привязки". 
  • Расходы по натуральным показателям – при выборе данной опции будет возможно планировать выполнение расходных объемов и расходов в количественном выражении в разрезе номенклатуры при планировании потребностей материальных ресурсов. Планирование расходных объемов при планировании расходов осуществляться не будет. Если опция включена, из табличной части "Распределение расходов" в документах Проектная задача убираются параметры "Способ привязки" и "Профиль / Дата привязки".

    • Важно! При включении опции "Расходы по натуральным показателям" также включается и блокируется для изменения опция "Планировать затраты на материалы и оборудование". При отключенной опции "Расходы по натуральным показателям" опция "Планировать затраты на материалы и оборудование" изменяется без ограничений.

  • Настройка распределения БДР по умолчанию – настройка распределения БДР по подразделениям с учетом трудозатрат (элемент справочника Настройки распределения БДР), используемая по умолчанию в элементах справочников Проекты и Портфели проектов, а также обработке Распределение БДР при распределении доходов и расходов проектных задач.

    • Учет ресурсов

  • Планировать трудозатраты по проекту – при указании опции, на закладке "Ресурсы" документа Проектная задача становятся доступны табличные части "Роли трудовых ресурсов" и "Исполнители". 
  • Обязательно указывать подразделения - если опция включена, при планировании трудозатрат становится обязательным заполнение подразделений для указанных ролей трудовых ресурсов. Опция доступна при включении опции "Планировать трудозатраты по проекту".

    • Важно! Опция "Обязательно указывать подразделения" обязательна для включения при планировании и актуализации работ по проектам руководителем структурного подразделения (например, при помощи обработки Панель руководителя подразделения и документов Прогноз трудозатрат по ролям и Планирование трудозатрат по трудовым ресурсам).

  • Учитывать период регистрации норм стоимости при расчете трудозатрат Ролей и ТР:
  • Если опция включена, стоимости трудозатрат ролей / трудовых ресурсов по проектной задаче будут рассчитываться по нормам, указанным в документах Регистрация стоимости ресурса / Регистрация стоимости ресурсов с учетом дат этих документов и распределения загрузки ролей / трудовых ресурсов по проектной задаче. В проектных задачах на закладке "Ресурсы" → "Роли трудовых ресурсов" будет заблокирована кнопка Пересчитать по норме и вместо колонок "Стоимость", "Общая стоимость", "Внешняя стоимость" и "Общая Внешняя стоимость" табличной части будут отображены колонки "Стоимость (ср.)", "Общая стоимость", "Внешняя стоимость (ср.)" и "Общая Внешняя стоимость", недоступные для редактирования (значение рассчитывается автоматически). 
  • Если опция выключена, стоимости трудозатрат ролей / трудовых ресурсов по проектной задаче будут рассчитываться по последним данным документов Регистрация стоимости ресурса / Регистрация стоимости ресурсов.
  • Внутренняя норма стоимости – внутренняя норма стоимости для заполнения по умолчанию в документах Проектная задача, Регистрация стоимости ресурса, Регистрация затрат материальных ресурсов. 
  • Внешняя норма стоимости – внешняя норма стоимости для заполнения по умолчанию в документах Проектная задача, Регистрация стоимости ресурса, Регистрация затрат материальных ресурсов. 
  • Планировать затраты на материалы и оборудование – при указании опции, на закладке "Ресурсы" документа Проектная задача становится доступна табличная часть "Материалы и оборудование". Опция доступна для изменения при выключенной опции "Расходы по натуральным показателям".
  • Планировать дополнительные затраты по проектной задаче – при указании опции, на закладке "Ресурсы" документа Проектная задача становится доступна табличная часть "Доп. затраты".

    • Учет движения денежных средств
  • Ведется бюджет движения денежных средств – опция определяет, будет ли вестись бюджет движения денежных средств по проекту.

    • Прочие опции
  • Хранить в версиях проценты готовности, статусы и фактические сроки проектных задач – если опция включена, при создании новой версии проекта, в ней дополнительно будут сохраняться данные о процентах готовности, статусах и фактических сроках проектных задач. У таких версий будет установлен признак "Версия включает данные выполнения" (для Текущей версии установлен всегда, независимо от значения опции). Особенности хранения данных выполнения при работе с версиями проекта (копировании, обновлении, загрузке) описаны в обработке Управление версиями проекта.
  • Использовать аналитику "Контрагент" / "Трудовой ресурс" для собственных сил – опция позволяет указывать контрагента либо трудовой ресурс для собственных сил в реквизите "Исполнитель" в расшифровках табличных частей документа Проектная задача (при включенных в проекте опциях "Доходы/расходы по подразделениям, объемам, натуральным показателям"). 
  • Разрешить создание обсуждений без указания проектной задачи – опция позволяет создавать задания с видом "Обсуждение" без привязки к конкретной проектной задаче.
  • Запретить руководителю проектной задачи изменять сроки задач других руководителей – опция запрещает сохранение изменений в структуре проекта сотрудником, который является Руководителем проектных задач, но не является Руководителем проекта, если эти изменения влияют на сроки задач других сотрудников.
  • Рассчитывать процент готовности при регистрации фактически выполненных объемов – опция позволяет рассчитывать проценты готовности проектных задач по план-фактным данным номенклатуры с признаком "Основной результат" из табличной части "Субпродукты" документа Проектная задача при проведении документов Регистрация фактически выполненного объема (в новых документах будет по умолчанию будет включена опция "Записывать процент готовности по доходным объемам", с возможностью отключить вручную).
  • Настройка дерева ключевых показателей – указывается настройка дерева ключевых показателей, элемент справочника Настройки дерева ключевых показателей, которая устанавливается по умолчанию для всех создаваемых элементов справочников Портфели проектов и Проекты. 
  • Настройка показателей для паспорта проекта – указывается вариант настройки обработки Панель руководителя, которая используется в карточке проекта на закладке "Показатели" по умолчанию.

    • Автоматическое назначение руководителя проектной задачи
  • Автоматически назначать руководителя подразделения основной роли руководителем проектной задачи – опция позволяет при назначении ролей трудовых ресурсов на проектные задачи через документ Проектная задача и/или обработку Структура проекта автоматически назначать руководителем проектной задачи сотрудника, зарегистрированного в качестве руководителя подразделения, которому принадлежит роль, указанная в текущей проектной задаче как "Основная роль". Если опция включена и в проектной задаче указана основная роль, то блокируется возможность изменять руководителя проектной задачи вручную при помощи документа Изменение руководителя проектной задачи.
  • Автоматическая установка признака "Основная" при добавлении роли – опция позволяет при назначении ролей трудовых ресурсов на проектные задачи через документ Проектная задача и/или обработку Структура проекта автоматически устанавливать признак "Основная роль" для первой назначенной роли. Опция становится доступной только при включенной опции "Автоматически назначать руководителя подразделения основной роли руководителем проектной задачи".

    • Группа "Распределение рабочего времени"

  • Время начала рабочего дня – время начала рабочего дня, используемое для подстановки по умолчанию в обработках Оперативная загрузка специалистов, Планировщик и в документе Табель учета рабочего времени.
  • Отключить проверку общего количества часов в документах по рабочему времени – опция указывает, нужно ли производить проверку физически возможного количества рабочих часов за день и за неделю в документах, регистрирующих распределение рабочего времени. Если настройка включена, перед записью будет производиться соответствующая проверка (в документе Распределение рабочего времени за неделю может быть распределено не более 168 часов (не более 24 часов за день), а в документе Табель учета рабочего времени – не более 24 часов). 
  • Разрешить списание рабочего времени по закрытым и завершенным задачам и закрытым заданиям – опция указывает, можно ли владельцам трудовых ресурсов отчитываться по использованию рабочего времени "задним числом". Если настройка включена, в документах Распределение рабочего времени за неделю, Табель учета рабочего времени, Прогноз трудозатрат по ролям и в обработке Планировщик (при создании табелей) доступна возможность внесения данных по проектным задачам в статусе "Завершена" или "Закрыта" и заданиям в статусе "Закрыто". Если константа отключена, вносить данные по таким задачам / заданиям невозможно. 

    • Важно! Данная константа оказывает влияние как на возможность отображения проектных задач в статусе "Завершена" или "Закрыта" и заданий в статусе "Закрыто" в документах отражения фактических трудозатрат (Распределение рабочего времени за неделю, Табель учета рабочего времени, Прогноз трудозатрат по ролям), так и на возможность проведения этих документов в системе. При отключенной константе, если был создан документ, отражающий факт трудозатрат по проектным задачам / заданиям, а затем эти задачи / задания были завершены / закрыты, проведение документа будет блокироваться.

  • Разрешить списание рабочего времени на проектные задачи проекта в статусах "Запланирован" и "Утвержден" – опция позволяет списывать рабочее время в документах Распределение рабочего времени за неделю, Табель учета рабочего времени и Прогноз трудозатрат по ролям на проектные задачи проектов, статус которых "Запланирован" и "Утвержден".
  • Разрешить списание рабочего времени на проектные задачи проекта в статусе "Остановлен" – опция позволяет Руководителю проекта списывать рабочее время, затраченное трудовыми ресурсами, для которых Руководитель проекта является владельцем, в документах Распределение рабочего времени за неделю, Табель учета рабочего времени и Прогноз трудозатрат по ролям на проектные задачи проектов, статус которых "Остановлен", вне зависимости от даты остановки проекта.

    • Важно!

  • Пользователи, кроме описанных выше, могут списать фактические трудозатраты по проекту в статусе "Остановлен" строго до даты остановки проекта (дата документа Остановка проектных работ), дата остановки в период списания не входит;
  • Опция оказывает влияние как на заполнение документов Распределение рабочего времени за неделю, Табель учета рабочего времени и Прогноз трудозатрат по ролям, так и на возможность проведения этих документов в системе.
  • Использовать расшифровку трудозатрат на проектных задачах – опция указывает, можно ли использовать механизм расшифровки трудозатрат по проектным задачам и рабочим заданиям. Если настройка включена, в документах Распределение рабочего времени за неделю доступна возможность внесения данных расшифровки фактических трудозатрат по дополнительному аналитическому разрезу. Если настройка отключена, вводить данные расшифровки невозможно. 
  • Регистрировать трудозатраты переходящей недели двумя документами – опция указывает способ, которым исполнитель будет отчитываться по трудозатратам, где конец одного месяца и начала другого выпадает на одну неделю. Если настройка включена, в документах Распределение рабочего времени за неделю данные по трудозатратам исполнитель заносит двумя документами – в первом документе исполнитель указывает трудозатраты за конец месяца, во втором – за начало следующего месяца. Если настройка отключена, то исполнитель указывает трудозатраты одним документом. 
  • Распределять рабочее время – опция указывает, как исполнитель может распределять свое рабочее время в документах Распределение рабочего времени за неделю и Табель учета рабочего времени. Закладка "Проектные задачи" документов может заполняться: 
  • Только по поручениям; 
  • Только по проектным задачам; 
  • По поручениям и проектным задачам: 
  • все проектные задачи и поручения; 
  • не распределять на проектные задачи с синхронизированными поручениями (поручениями, выданными автоматически, с включенной в них опцией "Синхронизировать с задачей").

  • Правило заполнения –  правило, которое определяет способ автоматического заполнения закладки "Проектные задачи" в документах Распределение рабочего времени за неделю и Табель учета рабочего времени, в зависимости от источников задания исполнителю. Значение правила выбирается из списка предопределённых вариантов:

  • Все проектные задачи и поручения;
  • Не распределять на проектные задачи с синхронизированными поручениями.

  • Группа для автоматически создаваемых направлений деятельности – константа устанавливает группу справочника Направления деятельности, которая будет являться родительской для создаваемой иерархии элементов справочника.
  • Кнопка Обновить связи проектов – кнопка запуска полного обновления связей проектов с направлениями деятельности. Полное обновление рекомендуется проводить при первой установке константы "Использовать связь проектов с направлениями деятельности".

    • Группа "Загрузка из сметы"

  • Использовать загрузку из сметы – константа определяет доступность обработки Загрузка из сметы. Обработка вызывается кнопкой Импорт и экспорт → Загрузка из сметы в справочнике Проекты и обработке Структура проекта.

    • Группа "Оповещения"

  • Использовать оповещения – константа влияет на возможность использования модуля "Оповещения". Если опция включена, в разделе "Администрирование" появляется пункт "Настройка оповещений" и становятся доступными все функциональные возможности данного модуля. Модуль "Оповещения" используется для настройки и отправки получателям уведомлений о любых событиях в системе.

    • Модуль "Оповещения" применим ко всему функционалу системы, механизм оповещений может быть настроен для любых объектов конфигурации.

    Для того чтобы система оповещений заработала нужно:

  • Включить ее использование в Параметрах подсистемы PM на закладке "Оповещения"; 
  • Включить в справочнике Виды событий события, оповещения о которых будет приходить пользователю; 
  • В справочнике Учетные записи электронной почты настроить системную учетную запись, от имени которой будут рассылаться письма. 
  • В справочнике Пользователи указать e-mail куда нужно отправлять письма. 
  • В разделе "Администрирование" в форме Персональные настройки в группировке "Оповещения" (либо в регистре сведений Подписки на оповещения, либо в справочнике Пользователи на вкладке "Подписки на оповещения") выбрать виды событий, по которым будут отправляться оповещения конкретному пользователю; 
  • Настроить время выполнения регламентных заданий "Обработка произошедших событий" и "Обработка очереди оповещений".

    • При генерации события, оно помещается в справочник Произошедшие события, затем регламентным заданием "Обработка произошедших событий" помещается в регистр Очередь событий для оповещений, далее регламентным заданием "Обработка очереди оповещений" отправляются уведомления адресатам и помещается в регистр Отправленные сообщения.

    Основные настройки

  • Адрес базы для навигационных ссылок – адрес текущей базы, который используется при формировании навигационных ссылок;
  • Кнопка Заполнить адрес базы по текущему соединению – позволяет получить и сохранить адрес текущей базы, который будет использоваться при формировании навигационных ссылок; 
  • Кнопка Показать подсказку адреса базы – отображает подсказку, включающую в себя вспомогательную информацию о назначении адреса базы, а также примеры адресов для различных вариантов баз; 
  • Срок хранения оповещений – задает количество дней хранения оповещений в регистре сведений Очередь событий для оповещений; 
  • Срок хранения событий – задает количество дней хранения событий в справочнике Произошедшие события; 
  • Виды событий – справочник Виды событий; 
  • Транспорт оповещений – справочник Транспорт оповещений; 
  • Виды получателей оповещений – справочник Виды получателей оповещений.

    • Очереди и история

  • Произошедшие события – справочник Произошедшие события; 
  • Очередь событий для оповещений – регистр сведений Очередь событий для оповещений; 
  • Отправленные сообщения – регистр сведений Отправленные сообщения.

    • Дополнительные параметры

  • Подписки на оповещения – регистр сведений Подписки на оповещения.

    • Группа "Защита конфигурации и ограничения доступа"

  • Менеджер лицензий СЛК – в данном разделе указывается путь к файлу данных (лицензионному ключу) – имя или ip-адрес сервера, порт сервера, параметры подключения и файлы защиты. Настройки подключения серий ключей защиты могут быть сохранены.

    • Ограничения доступа по проектам

  • Очередь пересчета ограничений доступа по проектам – регистр сведений Очередь пересчета ограничений доступа по проектам, в котором содержится очередь неотработанных событий; 
  • Открыть расписание регламентного задания пересчета ограничений по проектам – регламентное задание Пересчет ограничений доступа по проектам; 
  • Автоматические ограничения доступа по проектам – справочник Ограничения доступа по проектам, в котором содержится информация о составе профилей персональных групп доступа и входящих в них пользователях.

    • Важно! Если в разделе "Администрирование" → "Настройки пользователей и прав" → "Группы доступа" включен вариант работы "Производительный", после создания индивидуальной группы доступа нужно дождаться окончания выполнения регламентного задания "Обновление доступа на уровне записей".

    Группа "Дополнительные механизмы"

  • Пользователи операционной системы – обработка Пользователи операционной системы. 

    • Версии подсистем конфигурации
  • Табличная часть Версии подсистем конфигурации - содержит список всех подсистем, включенных в данную конфигурацию, с указанием их версий.
    • Варианты отчетов
  • Кнопка Обновить идентификаторы метаданных – по кнопке можно обновить идентификаторы метаданных. 
  • Кнопка Обновить варианты отчетов – по кнопке можно обновить варианты отчетов.
    • Фоновый пересчет сроков в структуре
  • Кнопка Включить фоновый пересчет сроков в структуре (Для всех пользователей и проектов) – кнопка включает опцию "Пересчитывать в фоновом режиме" в обработке Структура проекта для всех существующих в системе проектов и пользователей. Если опция включена, то при внесении изменений, данные структуры проекта (% готовности, длительность , сроки) будут пересчитываться фоновым заданием. 
  • Кнопка Выключить фоновый пересчет сроков в структуре (Для всех пользователей и проектов) – кнопка отключает опцию "Пересчитывать в фоновом режиме" в обработке Структура проекта для всех существующих в системе проектов и пользователей.
    • Группа "PM: Интеграция с Битрикс24"
  • Кнопка Настройки интеграции – открывает обработку "Настройки интеграции с Битрикс24".
